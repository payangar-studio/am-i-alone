Companion

The character itself, the first feature to build. Owner and modes come later (Ownership and modes).

In game

A companion looks, moves and animates like a player: the player animation mods (Fresh Animations, Not Enough Animations, Touch'n Motion, Better Combat...) animate it as they animate players. It is not a player: it takes no slot on the server, and it is not in the Tab list.

When nobody needs it, it lives like a villager: it stays where it is, and freezes when its area unloads. When it must keep the world alive around it (an owner taking it along, later), it does so exactly like a player. Whatever happens, it keeps everything it has, and it never changes visibly.

DecisionIts skin is one of the skins the mod ships, like an entity's variant: chosen when the companion is created, it never changes after. Players' own skins are not used.

Requirements

RequirementWhat it means
1. Animated like a playerOwned or not, by the player animation mods (EMF, ETF, Fresh Animations Player Extension, Not Enough Animations, Touch'n Motion, Better Combat, EMF Compat).
2. Cheap when nobody needs itA tavern may hold several: they cost like villagers and freeze with their area.
3. Like a player when it must keep the world aliveEvery effect of a player: the world around it stays loaded, monsters spawn, it counts for sleeping.
4. Not a player of the serverNot in the Tab list, not counted among the players, never in the way of a player who wants to join.
5. Nothing lost, nothing duplicatedWhatever happens to it, it keeps exactly its inventory, its equipment and everything else.
6. No visible changeChanging form does not show in game.

How it is built

A companion is one identity, its core, that lives on the server in one of two forms. Clients see one facade, and the form changes behind it.

  1. The core is the companion: identity, owner, mode, home. See Shared identity.
  2. It lives in one of two forms, one at a time, switched on the server. See The two forms and Switching forms.
  3. A client sees one facade, a remote player, which never changes when the form does. See Client facade.
  4. The facade is a player on the client, so the player animation mods animate it.

Classes

ClassWhat it is
CompanionThe core: identity, owner, mode, home, the rule that picks the form
CompanionFormThe interface both forms implement, through which they hand the core what is not vanilla plumbing
AnchoredCompanionThe anchored form, an entity extending Player
AnchorCompanionThe anchor form, extending ServerPlayer
ClientCompanionThe facade on the client, extending RemotePlayer
DecisionConstraints of the build: the player animation mods need no compatibility code of ours; no mixin while a vanilla or Fabric API does the job (one is needed, on the client, for the invisible switch).

How the parts talk

Each form carries its core and gives it through CompanionForm (the core, and the form as a vanilla entity); the core knows its current form only through the form that carries it. The switch is run on the server thread by the core, which reads its rule and asks for the other form (Switching forms).

DecisionUntil the other features exist, test commands stand in for them: one creates a companion (where the places will), one switches its form (where the modes will). Their syntax is decided with the issue of the first brick.
