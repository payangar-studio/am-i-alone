Am I Alone?

am_i_alone · both-required · Fabric · Minecraft 26.3

The mod adds companions: characters that look and animate like players, but that nobody controls. Some live unowned in village taverns or structures; a player can make one their own, the way one tames a wolf, and give it orders (follow, stay, wander, stay around its home).

The two forms

Decision On the server, a companion always has exactly one of two forms. It takes the world-player form only when it has an owner and its mode asks it to load the world; otherwise the stored form.
  1. Owned, and given a mode that loads the world: it becomes a player of the world.
  2. A mode that does not load the world, or losing its owner: it goes back to being an ordinary entity, in the chunk where it stands.
  3. The stored form is saved with its chunk, like a villager: see Saving.
  4. A player is never stored in a chunk, and this one is not a connected player whose file vanilla writes: the mod saves it. See Saving.

The core and the forms

Decision The two forms extend different vanilla classes (Player and ServerPlayer), so the logic cannot live in a shared parent class. It lives in an object, the companion's core, that the form carries.
  1. The core holds the companion's state and logic. It is saved in the form's data and moves from one form to the other with it.
  2. The forms only do what vanilla requires, and hand the rest to the core through an interface both forms implement.
  3. The Brain lives inside the form, as in any vanilla creature, and its memories are saved with it. It accepts any living entity, so a behaviour such as "follow the owner" is written once for both forms.
  4. The motor turns the Brain's intentions into player inputs. Vanilla's pathfinding requires a Mob, and neither form is one: the motor is ours to design.
Fact Both forms override getType() and typeHolder() to carry am_i_alone:companion, but a private field of Entity still holds minecraft:player, read directly by a few methods (default name, loot table, size, network update interval). These values are a player's today, so they match; a test has to cover this coupling.
Fact Player takes its UUID back from its profile on every load: a stored form reloaded with its chunk would change identity. The core saves and restores the companion's profile (UUID, name, skin).

Saving

Decision Each form is saved where vanilla keeps that kind of thing, never in the players' files.
Stored formPlayer form
WhereWith its chunk, in the world's entity filesIn the mod's data, saved with the world (a Fabric global attachment)
WhenWhen vanilla saves or unloads the chunkBefore each world save (BEFORE_SAVE), and when the server stops
On restartComes back with its chunkRecreated at startup, at its position; loads its chunks again

Chunks and the mod's data are written during the same save: a crash between two saves brings both back to the same moment, with no companion lost or duplicated. A crash while the save is being written is not covered; vanilla has the same window between the players' files and the chunks.

Fact At startup, vanilla saves the world before the server is declared started. Saving the world-player forms then would overwrite the data with an empty list: it only happens once they are restored.

Sides

mod.toml sets both-required: the mod runs on the server and the client.

  1. Both forms announce the type am_i_alone:companion in their spawn packet; the factory of that type builds a ClientCompanion on the client, as vanilla does for the Mannequin.
  2. Then the client receives a player's synced data (health, pose, equipment...), the same for both forms.
  3. No profile is sent, which keeps the companion out of Tab. The client therefore knows neither its skin nor its name: see the question below.
Fact Checked in game (prototype on branch spike/companion-forms): Fresh Animations Player Extension (an EMF pack), Not Enough Animations, Better Combat and Touch'n Motion animate the companion in both forms. ETF and EMF Compat were loaded but not checked one by one. Better Combat animates an attack, but only starts one from a real client's key press: making a companion attack will take code of ours.
